# 开发日志 — 2026-07-09

## 今日完成

### 页面无法加载问题排查与修复

**问题现象**：浏览器访问 http://127.0.0.1:8123 一直显示"加载中"，页面白屏不渲染。服务端日志正常（200 OK），curl 也能拿到完整 HTML。

**排查过程**：

1. **ECharts CDN 阻塞渲染（根因 #1）**
   - `index.html` `<head>` 中引用了 `https://cdn.jsdelivr.net/npm/echarts@5.5.0/dist/echarts.min.js`
   - 无 `async`/`defer`，脚本在 `<head>` 中是渲染阻塞的
   - 网络无法访问 jsdelivr CDN，导致脚本下载挂起，页面永远停在"加载中"
   - 测试 `test.html`（无任何依赖）可正常打开，确认是 CDN 问题

2. **注释 CDN 依赖**
   - 将 ECharts CDN `<script>` 注释掉，页面完全本地运行
   - `app.js` 中图表相关函数（`renderCumulativeChart`、`renderHoldingChart`、chart tab 切换）加了 `typeof echarts === 'undefined'` 守卫
   - 图表功能暂时不可用，其余所有功能正常

3. **Safari 缓存导致旧页面持续被使用（根因 #2）**
   - 注释 CDN 后 `curl` 能拿到新版 HTML，但 Safari 仍显示旧页面
   - 用 `/?v=2` 绕过缓存后正常，确认是 Safari 缓存了旧版 `index.html`（含 CDN 脚本的版本）
   - 添加 `NoCacheMiddleware` 设置 `Cache-Control: no-store` + 剥离 ETag/Last-Modified
   - 中间件首次实现在 `MutableHeaders` 上错误调用了 `.pop()`，导致 500 错误，已修复为 `del response.headers[h]`

4. **改造 HTML 服务方式**
   - Safari 对已缓存的 `/` 路径非常顽固，即使加了 no-store 仍使用旧缓存
   - 将 `index.html` 从 `StaticFiles` 挂载中独立出来，改为通过 `@app.get("/")` 路由直接返回 `HTMLResponse`
   - 该路由没有 ETag、Last-Modified、Accept-Ranges 等缓存相关头，Safari 无法缓存

5. **OCR Parser 优化**（WIP，未提交）
   - `_ocr_tesseract` 函数增加预处理：OTSU 自适应二值化、中值降噪、RGBA→RGB 扁平化、300 DPI 放大
   - 移除字符白名单（会强制 legacy 模式，破坏 LSTM 中文识别）
   - Tesseract 配置改为 `--oem 1 --psm 6`（LSTM only）
   - 新增 `_compute_otsu_threshold` 辅助函数
   - 新增中文语言包安装检测提示
