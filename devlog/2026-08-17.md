### 修复 Safari 无法加载页面问题（服务端加固）
上次遗留：Safari 直接访问 http://127.0.0.1:8123 一直"加载中"，带 query string 的 URL 正常。

**根因分析**：
- / 路由只注册了 GET，HEAD / 返回 404 —— Safari 缓存校验使用 HEAD 请求，404 会让页面被判定为缺失
- 响应缺少显式 Cache-Control，Safari 会基于 ETag/Last-Modified 做启发式缓存，导致旧页面（含 CDN 阻塞脚本的版本）被反复使用
- devlog 2026-07-09 提到的 NoCacheMiddleware 实际上不在代码里（可能未保存）

**修复**：
- [x] 新增 NoCacheMiddleware：所有响应强制 Cache-Control: no-store, no-cache, must-revalidate, max-age=0 + Pragma: no-cache + Expires: 0
- [x] 中间件剥离 ETag/Last-Modified/Accept-Ranges 缓存验证头（修复 bytes vs str 比较 bug，之前过滤不生效）
- [x] / 路由改为 @app.api_route(methods=["GET", "HEAD"])，HEAD 返回 200 无 body
- [x] 前端资源版本号 v=23 → v=24，确保 Safari 拉取新文件
- [x] 实测：HEAD / → 200、所有静态资源 200 + no-store、带旧 ETag 的条件请求返回 304（文件未变，正确）
- [x] Edge 无头实测页面完整渲染：XIRR 9.55%、14 条交易、图表 canvas 正常
