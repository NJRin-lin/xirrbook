# 开发日志 — 2026-08-17（OCR 修复补充）

## 问题：OCR 提示 Tesseract 未安装，但本应使用 macOS Vision

### 根因（三层）
1. **前端错误文案误导**：app.js 的 catch 分支写死了『OCR 服务不可用。请确认已安装 Tesseract』，
   无论 Vision 失败还是网络错误都显示这个，与实际情况无关
2. **后端 500 文案同样误导**：routes/ocr.py 写死『请确认 Tesseract 已安装』
3. **Vision 链路缺陷**（真实失败原因）：
   - `swift vision_ocr.swift` 每次调用都重新编译，极慢且可能超时
   - Vision 对超长滚动截图（如 886×33065）返回『no text recognized』
   - 超长图 fallback 到 Tesseract 时报『Image too large』崩溃（500）
   - vision_ocr.swift 行分组逻辑有 bug：用字符串匹配找行首对象，重复文本会错乱

## 修复

### ocr_parser.py
- [x] `ocr_image()` 返回结构改为 dict：{text, engine, error}，engine 区分 vision/tesseract
- [x] `_ocr_vision()`：swiftc 预编译成二进制缓存（首次编译后续复用，快 ~10 倍）
- [x] swiftc 加 `-Xcc -fmodules-cache-path` 重定向 clang 模块缓存，规避权限问题
- [x] 超长图切片：>4000px 高的图按 4000px 块切片 + 100px 重叠，逐块 Vision 识别后合并
- [x] 图片 magic bytes 识别真实格式（PNG/JPG/GIF/WEBP/BMP），Vision 按正确后缀解码
- [x] `_ocr_tesseract()`：最长边 >8000px 时缩放，避免『Image too large』崩溃
- [x] **解析器 bug 修复**：cancel 检查窗口收窄到「类型行→日期行」范围，
NaN
