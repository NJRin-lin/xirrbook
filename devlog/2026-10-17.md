# 开发日志 — 2026-10-17

## 修复：市值重复计算

- 新增统一估值解释模块，将「当前市值」「市值更新」与真实现金流分开。
- XIRR 采用所选记录中每个账户、标的最后一次市值及记录日期，同日按记录 ID 决定先后。
- 历史市值记录即使存有正现金流，也不计入真实投入、收回或累计净现金流；无需迁移原数据库。
- 手动录入、编辑、OCR 导入和 CSV 导入统一保存估值现金流为 0，保留合法的零市值，拒绝缺失、负数、非有限市值。
- CSV 去重包含市值金额，并兼容历史正现金流的估值记录，避免同日不同估值被误跳过或旧 CSV 被重复导入。
- 同一天的投入和估值不生成没有时间意义的年化收益率。
- 修正文案，不再建议将估值伪装成卖出，曲线明确标为累计净现金流。

## 修复：未填写股数时隐藏持仓

- 持仓与持仓饼图支持只有金额的记账方式。
- 缺失股数时，份额、均价、成本和未实现盈亏不再假定为 0；展示累计净投入（扣除卖出、不扣分红）和累计盈亏（含分红）。
- 完整股数记录按移动平均成本计算，部分卖出同步扣减持仓成本。
- 清空或无可展示持仓时，饼图清除旧数据。

## 修复：OCR 金额误读

- 保留独立数字金额行，包括正负号、货币符号和千位分隔符。
- 整体匹配金额后再归一化，防止 `12.000.00` 被截成 `12.00`。
- 金额提取排除日期、时间、带标签的基金代码，缺少金额时不会从日期中拼凑。
- 限制搜索范围，缺失金额的记录不会借用下一笔金额，其日期也不会被下一笔占用。
- 日期使用真实日历校验，不再固定限制在 2020–2030 年。

## 当前边界

- 日期筛选只选取范围内的记录，尚未提供期初资产估值补入，不能把任意筛选范围视作完整区间收益率。
- 估值采用用户录入的日期和金额；交易后需要更新市值，系统不会自动获取行情。

## 完整基金名称解析修复

- 先创建 GitHub 分支 `fix/ocr-complete-fund-names`，再修改名称解析规则。
- 排查发现 Vision 原始文字完整保留了基金名称，但旧正则只接受中文主体加一个英文后缀，在 ETF 后遇到「联接」时提前结束。
- 名称规则支持中文、英文缩写、指数数字、括号和份额类别混合，例如「博时黄金ETF联接C」「南方中证500ETF联接A」「摩根标普500指数（QDII）A」。
- 兼容 Vision 在 ETF、联接和类别字母之间插入空格；QDII 等基金缩写不再作为独立股票代码优先返回。
- 后端 42 项回归测试通过，包含混合基金名称、A/C 区分、日期金额状态隔离、撤销记录过滤及股票代码兼容。
- 用户提供的截图仅交给本机 OCR 复查，没有保存进仓库或重新导入交易，也未自动重命名现有标的。


## 区间 XIRR（开发分支待用户测试）

- GitHub 分支：`feat/period-xirr`。本次明确不合并 main，必须等用户实际测试并明确授权。
- 起止日交易均计入；期初采用起始日前一天收盘市值，期末采用结束日收盘市值。只填起始日时截止今天，只填结束日时从最早记录开始。
- 每个账户、标的独立检查估值。缺少任一边界时不显示部分组合的收益率，而是列出缺失估值并提供自动填入基金、账户、日期的补录入口。
- 不把旧的正市值平移至边界；明确空仓且之后无现金变动可按 0 处理，完整记录中的区间内首次投入期初按 0。
- 仅有卖出金额不能证明全部清仓，需用户补充零市值。期初估值只参与计算，不生成虚拟买卖，也不计入新增投入。
- 新增区间盈亏、期初期末市值说明；不设置日期时保持全历史模式。持仓和图表仍使用全部记录，界面注明范围。
- 补录保留对应账户，避免多账户同名基金的估值混用。
- 后端 64 项测试通过；前端回归包含区间标签、现金投入与估值区分、缺估值提示、补录日期/基金/账户自动填写、切回全历史模式。
- 独立临时数据库浏览器实测：筛选 2025 全年时准确提示缺少 2024-12-31 期初市值，点击补录 1200 后显示期末 1320、区间 XIRR 10.00%、盈亏 120、新增投入与实际收回均为 0。
- 浏览器补录仅写入临时数据库；未修改用户日常交易数据。


## 支付宝基金录屏导入（开发分支待用户测试）

- 先创建并推送 GitHub 分支 `feat/video-import`，基于尚未合并的 `feat/period-xirr` 继续开发。两项功能均需用户测试并明确授权后才可合并 main。
- 增加录屏导入入口，支持 MP4/MOV/M4V，多段依次处理；单段最多 3 分钟、200MB，每批最多 3000 条候选。当前 Mac 已有 FFmpeg/ffprobe，无需云端服务。
- 后台任务每半秒抽帧并补取末帧，显示进度，支持取消与过期清理。解码有时长、分辨率、执行超时限制；本地解码仅允许 file/pipe 协议。完全相同像素的画面跳过，避免近似画面去重误吞金额变化。
- 相邻画面的完整记录按日期、基金、业务类型、金额与交易时间整理为候选组，保持同屏相同交易的数量。候选组默认待确认，可展开逐次观察；缺字段记录保留供补录或明确跳过。
- 点击来源定位录屏时间点、抽帧原图及文字，也可播放本地原始录屏。同一交易时间出现不同金额时强制逐条确认，批量首条操作不会自动选定冲突金额。
- 真实录屏发现并修复：基金标题中的“红利”误触发分红、括号基金代码误作金额、完整标题被代码替代、滚动顶部残留日期抢占下一笔日期、以“份”为单位的分红误当作现金。份额分红保留为金额待核对，不凭空换算；交易时间保留秒数。
- 原视频临时副本识别结束即清理；抽帧关闭时清理，完成后最多保留 30 分钟。浏览器保留原文件预览，不将视频写入交易数据库。
- 自动验证：84 项 Python 测试通过，既有前端与录屏核对逻辑测试通过，包含真实 FFmpeg 解码合成短视频、失败画面继续处理、任务取消、大小/时长限制、同屏重复交易、冲突金额与清理行为。
- 用户提供的约 15 秒 MOV 完整经过本机 Vision：32 个采样画面，3 个完全相同画面跳过，其余 29 个画面均成功识别；251 次观察保留为 40 条候选。明确跳过缺字段候选、确认重叠并人工核对一处金额冲突后，20 条现金交易成功导入独立临时数据库。两笔以份额显示的分红仍需核对，不能作为现金金额直接导入。
